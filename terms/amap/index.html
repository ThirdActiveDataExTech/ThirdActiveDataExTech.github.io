AMAP: Active Metadata Application Profile

네임스페이스 https://thirdactivedataextech.github.io/terms/amap/ · 접두어 amap: · 버전 1.0

AMAP은 W3C DCAT 3.0을 확장한 어휘입니다. 형식이 서로 다른 원본 메타데이터(JSON, XML, RDF, SDMX 등)를 원본 그대로 보존하면서 DCAT의 공통 속성으로 함께 표현하고, 원본의 어느 속성이 어느 표준 속성에 대응하는지를 유사도와 근거까지 포함해 기록할 수 있게 합니다.

개요

데이터 카탈로그는 여러 출처에서 메타데이터를 모읍니다. 출처마다 속성 이름과 구조가 다르기 때문에 공통 어휘(DCAT)로 옮기는 매핑이 필요하고, 그 과정에서 두 가지가 자주 사라집니다. 하나는 공통 어휘에 자리가 없는 원본 정보이고, 다른 하나는 "왜 이 원본 속성을 이 표준 속성으로 옮겼는가"라는 판단 과정입니다. AMAP은 이 둘을 남기기 위해 세 가지 클래스를 둡니다.

클래스이름역할
amap:CatalogEntry카탈로그엔트리카탈로그에 등록된 데이터 하나를 나타내는 항목. 원본 메타데이터를 그대로 보존하면서 제목·발행자·주제 같은 공통 속성을 DCAT 어휘로 함께 표현하고, 원본 속성 항목(MetadataEntry)과 속성 매핑 관계(ColumnRelation)를 연결하는 기준이 된다.
amap:MetadataEntry메타데이터엔트리원본 메타데이터의 속성 하나. 원본 안에서의 위치(경로)와 값을 그대로 기록한다. 공통 속성으로 옮기지 못한 원본 정보도 이 항목으로 남는다.
amap:ColumnRelation컬럼관계원본 속성 하나가 어떤 표준 속성에 대응하는지를 기록한 매핑 관계. 원본 경로, 대상 표준 속성, 유사도 점수, 대표값 여부, 우선순위, 판단 근거를 담는다.

세 클래스는 amap:CatalogEntry를 중심으로 연결됩니다. 카탈로그엔트리는 amap:hasMetadataEntry로 원본 속성 항목을, amap:hasColumnRelation으로 매핑 관계를 가집니다. 원본 속성 항목과 매핑 관계는 같은 amap:sourcePath 값으로 서로 대응되고, 매핑 관계의 amap:targetProperty가 DCAT 쪽 표준 속성을 가리킵니다. 카탈로그엔트리 자체에는 dct:title, dct:publisher, dcat:theme 같은 DCAT·Dublin Core 속성을 그대로 씁니다.

매핑 관계를 적는 방법

원본 속성 하나마다 amap:ColumnRelation을 하나 만들어 어느 표준 속성에 대응하는지 적습니다. 대응 방식은 네 가지로 나뉩니다.

방식언제예
직접 매핑원본 속성이 표준 속성과 뜻이 같을 때name → dct:title
간접 매핑뜻이 비슷하거나 값을 변환해야 할 때. 유사도 점수로 대응 여부를 판단한다additionalType → dcat:theme (분류 문자열을 주제 개념으로)
다대일 매핑원본 속성 여러 개가 한 표준 속성에 대응할 때. 대표값 하나에 amap:isPreferred를 참으로 둔다한국어 제목(대표값)과 영어 제목 → dct:title
미대응대응되는 표준 속성이 없을 때. 매핑하지 않고 amap:MetadataEntry로만 보존한다legislation (근거 법령)

유사도 점수는 0.0~1.0이며 1.0은 완전히 같은 속성입니다. 자동으로 매핑한 경우에는 어떤 규칙이나 모델을 썼는지, 어떤 후보를 검토해 무엇을 택했는지를 amap:evidence에 남겨 두면 나중에 같은 결과를 재현하거나 검토할 수 있습니다.

예시

Schema.org(JSON-LD)로 제공된 데이터셋 메타데이터를 카탈로그엔트리로 표현한 예입니다. 원본의 name은 dct:title에 직접 대응되고, additionalType은 주제 분류로 간접 대응되며, legislation은 대응되는 표준 속성이 없어 원본 속성 항목으로만 남습니다.
